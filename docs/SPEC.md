# Runner — Unified Specification

**Current as of v1.11 (build 25), 2026-09-07.** This is the single description
of what the app does today. It replaces reading fifteen epic designs to answer
one question.

The per-epic documents in `docs/superpowers/specs/` and `docs/superpowers/plans/`
are kept as a **log**: they hold the reasoning, the alternatives rejected, and
what was true at the time. They are history and are not maintained. When they
disagree with this file, this file wins; when this file disagrees with the code,
the code wins — and this file is wrong and should be fixed.

**Maintaining it:** update the section a change touches, in the same commit.
Section 15 (Invariants) is the part worth reading before changing anything in
`Core/Recording`.

---

## 1. Product

A personal iPhone fitness app. It turns daily steps and GPS-recorded
runs, walks and rides into a single daily **points** score, keeps a streak, and
draws the routes. Apple Health is the system of record; the local store is a
rebuildable cache.

One user, one device, no accounts, no server, no analytics.

## 3. Screens

Three tabs (`RootTabView`), plus modals:

- **Today** — points ring, streak, weekly recap, weekly goal row, PR ticker,
  Monthly Wrapped banner.
- **History** — heatmap, day detail, workout detail, insights/trends,
  per-activity hubs, records, split analytics, Wrapped archive.
- **Routes** — the map surface.

Modals: **Record** (full-screen cover), **Settings**, **Profile** (body
metrics, pushed from Settings — it gates every calorie number), **Trophy
Room**, **Workout Summary** (with celebrations), **Monthly Wrapped**.

## 4. Points engine

Pure, in `Core/PointsEngine`. Exact rules:

```
stepPoints    = min(steps / 100, 200)
workoutPoints = round(km × rate),  rate: run 15, walk 10, bike 6
multiplier    = min(1.0 + 0.05 × streakBefore, 1.5)
total         = round((stepPoints + workoutPoints) × multiplier)
```

A day is **gold** when `total >= goal` (default goal 100, set in Settings). The
streak increments on a gold day and resets to 0 otherwise.
`LedgerBuilder.build` walks days in order, so the multiplier always uses the
streak *before* that day. `livePoints` reuses `workoutPoints` verbatim, so the
live HUD can never disagree with the summary shown at the finish.

## 5. Data & persistence

**`DayLedger`** (unique by date) — steps, the points breakdown, the goal and
weekly target *in effect that day*, gold flag, streak after, plus derived
calories/distance/active seconds. Every added column carries an inline default
so SwiftData lightweight-migrates existing stores.

**`WorkoutRec`** (unique by id) — type, start/end, moving seconds, distance
(+`distanceEstimated`), points, route blob, split seconds, `source`
("runner" | "external"), `hkSynced`, calories (+`caloriesFromHealth`), CO₂
(+`co2FromHealth`), `autoStarted`.

**A workout with no distance is not stored.** `finish()` refuses to produce one
on every manual path, the import loop skips them, and `purgeZeroDistanceWorkouts()`
runs on every sync to clear anything a past build left behind. A "0.00 km run"
earns no points, draws no route and carries no pace — it is always the residue of
a session that failed, never one that happened. The auto-walk path is the single
exception *during* finish (`requiringDistance: false`), because a detected walk
legitimately has zero GPS metres until the Health backfill runs; it then applies
its own, stricter 100 m floor.

**`UserProfile`** — height, weight, birth date, sex, each with a manual-override
flag so a Health value never silently overwrites a typed one.

Derived values (points, calories) are **persisted at save time** from the
metrics in effect then: a workout keeps the calories it was burned at even if
weight changes later.

## 6. Apple Health

`SyncCoordinator` owns the sync. A rolling **90-day** window (`windowDays`)
refreshes on foreground; a **one-time full-history backfill** runs once and is
recorded by a flag, after which history reaches back 52 weeks. A second one-time
backfill (`v14MetricsBackfilled`) recomputed CO₂/calorie provenance.

Real Health values are preferred over estimates and marked as such
(`caloriesFromHealth`, `co2FromHealth`, `distanceEstimated`). Rides imported
without distance get an estimate; Bixi rides carry CO₂ in workout metadata,
with `CO2Estimator` as the fallback. Settings has a HealthKit diagnostics screen.

Workouts whose HealthKit source is Runner itself are imported **only when no
local row already claims that `(type, start)`** — normally never, since the app
wrote that row at record time, but after a delete-and-reinstall the HealthKit
samples survive and the SwiftData rows do not. Skipping them outright used to
make every run Runner ever recorded vanish from History, Routes, records and
badges while still counting toward points and streaks.

The import is one transaction (`upsertWorkout(save: false)` + a single commit),
and rolls the context back if any row throws.

## 7. Recording pipeline

`Core/Recording`. This is the most-revised part of the app and the one with the
most hard-won constraints — read section 15 before changing it.

### 7.1 Location intake

`SystemLocationProvider`: best accuracy, `.fitness`, background updates on,
`pausesLocationUpdatesAutomatically = false`, and **no distance filter**
(`kCLDistanceFilterNone`).

`LocationFilter` decides whether a sample joins the route — **a separate
question from whether the user is moving**:

| Rule | Value |
|---|---|
| Max horizontal accuracy | 30 m |
| Max sample age | 10 s |
| Min displacement to accept | 3 m |
| Gap threshold | 15 s |

A sample after a gap is marked so the map never draws a line the user did not
walk, and its distance is not credited.

### 7.2 Speed estimation

`SpeedEstimator` answers "how fast is he moving *now*":

1. CoreLocation's Doppler `speed` when it is valid (`>= 0`) — it is measured,
   not differenced.
2. Otherwise, displacement over a baseline of **at least 5 s**
   (`minBaseline`), anchored on the *newest* fix that old, with the window
   trimmed at **12 s** (`maxBaseline`).
3. Otherwise `nil` — "no evidence yet", which leaves every accumulator alone.

Never differences two consecutive fixes: over a 1–3 s baseline, GPS noise alone
reads as 1–3 m/s.

### 7.3 Auto-pause

`AutoPauseDetector`, fed only samples that pass the accuracy rule above.
Farid's deliberately **aggressive** profile:

| | run / walk | bike |
|---|---|---|
| Pause below | 0.5 m/s | 1.0 m/s |
| after | 6 s | 10 s |
| Resume dwell | 1 s | 1 s |
| Instant resume at | 1.5 m/s | 3.0 m/s |
| Plausibility ceiling | 8 m/s | 25 m/s |

A speed above the ceiling carries **no information at all**: it neither resumes
a paused session nor resets a pause accumulator.

### 7.4 Motion gate

`MotionGate` is CoreMotion's second opinion, and it is **one-directional: it may
only refuse to start or resume a run, never cause or delay a pause.** It vetoes
only on a confident, current `stationary` classification (backstop:
`maxSampleAge` 300 s). Unknown, low-confidence, stale, absent — all abstain.

The recorder holds its **own** `SystemMotionActivityProvider`, separate from the
auto-walk one.

### 7.5 Session lifecycle

- **Armed**: frozen at `.autoPaused`, clock not running, no samples accepted.
  Un-freezes on the first movement the estimator and the gate both accept, and
  `startedAt` rebases to that moment. One-shot: later pause cycles never rebase.
  Times out after **10 minutes** and discards.
- **Recording**: wall time accrues sample to sample, uncapped — GPS gaps keep
  the timer running; only pauses stop it.
- **Checkpoints** every **30 s** to `CheckpointStore`, including whether the
  session was manually paused, so a relaunch rehydrates the real state.
- **Finish** trims the tail to the last genuinely-moving sample, and refuses a
  session that covered no distance — announcing `.runCancelled` rather than
  going silent, since silence reads as a save.

### 7.6 Session trace (diagnostics)

`SessionTrace` writes one CSV row per sample to `Documents/Diagnostics/`:
timestamp, lat, lon, accuracy, sensor speed, speed actually used, state, armed,
motion verdict, and the transition if there was one. The newest **8** sessions
are kept; auto-detected walks are not traced. `UIFileSharingEnabled` exposes the
folder in the Files app.

`TraceReplay` (test target) reads a trace back into locations, rebasing
timestamps so the freshness check does not discard an old run. **A real
misbehaving run becomes a permanent regression test** — use it instead of
inventing a noise model.

## 8. Hands-free control

- **Live Activity** — Lock Screen and Dynamic Island, with Pause/Resume/Finish.
  Controls use `.invalidatableContent()` so a tap reads as pending during the
  0.5–2 s iOS needs to wake the app. Status changes short-circuit the update
  throttle.
- **Lock Screen / control widget** — arms a run **without forcing an unlock**.
  The app syncs to the live session when it next comes to the foreground
  (`presentActiveSessionIfNeeded`), never at tap time.
- **Siri** — five `LiveActivityIntent`s (`.alwaysAllowed`) plus a status query,
  French phrases in `AppShortcuts.xcstrings`, `INAlternativeAppNames` =
  Course / Run.
- **Spoken cues** (`RunAnnouncer`, AVSpeechSynthesizer, ducking `.spokenAudio`):
  started, paused, resumed, saved, cancelled, location denied, and each
  kilometre. From km 2 both paces are announced and named — "Dernier
  kilomètre : 5 minutes 38. Moyenne : 5 minutes 50 par kilomètre" — because one
  number called "Pace" reads as the whole run's. Km 1 keeps a single pace.
  Siri entry points pass `announcing: false` so only Siri speaks.
  **Auto-started sessions announce nothing, ever.**

## 9. Auto-walk detection

`WalkDetector` + `AutoWalkCoordinator`. Walking for **5 minutes** (`startAfter`)
opens a walk; **5 minutes** without walking (`stopAfter`) closes and saves it,
with a **60 s** grace for gaps. Walks under **100 m** are discarded as misreads.
On foreground, the last **30 minutes** of CoreMotion history replay through the
detector so a walk begun with the app closed still lands.

**Fully silent by design** — no banner, no prompt, no announcement. Auto-started
sessions get no Live Activity and no trace.

## 10. Derived features

All pure math, all unit-tested:

- **Goals** (`GoalsMath`) — weekly consistency (gold days/week, default 3) and
  per-activity weekly distance.
- **Trophies** (`TrophyMath`) — distance ladders (10/25/50/100/250/500/1000 km;
  bike 25→2500), count ladders (10/25/50/100), weekly streaks (4, 12), plus
  personal-record achievements celebrated at the finish.
- **Monthly Wrapped** (`WrappedMath`) — story-card recap, Today banner + History
  archive. No sharing.
- **Insights / Hubs** (`InsightsMath`, `HubMath`) — trends, year-over-year,
  progression ranges, consistency, records, per-activity.
- **Splits** (`SplitStats`) and **History** (`HistoryMath`) — heatmap, series.

## 11. Calories & CO₂

`CalorieEngine` — MET tables per activity interpolated by speed, everyday
walking at MET 3.0 / 4.5 km/h, stride estimated from height and sex, calories
per step from weight. Health's `activeEnergyBurned` wins when available.
`CO2Estimator` + `Co2Metadata` produce CO₂ avoided, preferring workout metadata.
Both write paths apply it: a ride Runner recorded itself gets the same estimate
as one imported from Bixi, and a HealthKit retry preserves it rather than
resetting the column.

## 12. Design & i18n

Dark-only "Electric Night". Design tokens and haptics in `DesignSystem`.

Every user-facing string is in `Localizable.xcstrings`, English + French, both
complete. **Edit that file textually — never round-trip it through JSON**; doing
so once produced five duplicate keys.

## 13. Testing

436 tests, Swift Testing (`@Test` / `#expect`), 1 known warning (HealthKit's
`totalEnergyBurned`, deprecated in iOS 18 and deliberately kept as the
`activeEnergyBurned` fallback for sources that only set the aggregate). Shared
test doubles live in `Fixtures.swift`, `FakeHealthStore.swift` and
`FakeMotionActivityProvider.swift` — not inside whichever test file happened to
need them first.

Release contract tests assert **floors, not literals**: a test that pinned the
exact marketing version failed on every bump and trained everyone to ignore a
red suite.

All engines are pure and tested directly. Seams (`LocationProviding`,
`MotionActivityProviding`, `HealthStoring`, `Announcing`,
`LiveActivityPresenting`, `AudioSessionControlling`) let every path run without
hardware. `HandsFreeReleaseContractTests` pins release-critical French strings
and provider configuration.

Note: `#expect(d.update(…) == false)`, never `#expect(!d.update(…))` — the macro
captures the receiver immutably and a `mutating` call will not compile.

**Coverage, measured 2026-09-07** (the scheme gathers it on every run):
37.6% of the app target. That single number hides the only distinction that
matters:

| Stratum | Coverage |
|---|---|
| `Features/*` non-view (`HubMath`, `InsightsMath`, `TrophyMath`, `WrappedMath`, `ActivityStats`, `SplitStats`, `GoalsMath`, `RouteSelection`, `WrappedBannerState`) | 97.7% |
| `Core/` + `App/` (recorder 97.8%, sync 97.0%, store 97.9%, model 90.7%) | 74.2% |
| SwiftUI views | **13.7%** |

The view figure is not verification — **no test asserts anything about any
view**. The unit bundle is hosted in the app, so launching it renders
`RootTabView` and `TodayView` once; that incidental render is the whole 13%,
which is why `HistoryView` and `RoutesView` read 0.00% (they need a tap nobody
makes).

This is where the defects are. The 2026-09-05 audit found 20, and its fix
commit touched twelve view files — every one of them at 0.00%. The suite was
green throughout. The answer is not "write UI tests": four of those defects
were pure functions wearing a `View` costume, and they now live in
`RouteSelection`, `WrappedBannerState`, `HubChartRange.series` and `AppModel`,
all covered, pinned by `ViewDerivationTests`. Move that kind of derivation out
of the body and the 97.7% stratum covers it; what stays in a view body should
be layout.

The lower-coverage seams, and why: `LiveActivityController` 1.8% and
`SystemMotionActivityProvider` 6.2% are ActivityKit/CoreMotion and are covered
instead through their extracted seams (`LiveActivityPresenting`,
`LiveActivityRequestGate`, `LiveActivityOrphanSelector` — all 100%).
`HealthStore` stays at 19.6% and that number will not move much: the branching
that mattered (`resolvedDistanceMeters`, the cycling → walk-run → aggregate
fallback that exists because Bixi rides read 0 km, and `resolvedEnergyKcal`) now
lives in `HealthMappers` at 100%, and what is left behind is the HealthKit query
plumbing — reachable only from a real phone, and correctly so.

## 14. Build & deploy

`Runner.xcodeproj` is generated and gitignored. **`xcodegen generate` also
rewrites both `Info.plist` files** from `project.yml` — bump `CFBundleVersion`
there (two places: app and widget), never with PlistBuddy.

`scripts/deploy.sh` does the whole device deploy. Two gotchas it cannot solve:

- **The iPhone must be unlocked**, or both the device-destination build and the
  install fail with `kAMDMobileImageMounterDeviceLocked`. Building with
  `-destination 'generic/platform=iOS'` compiles and signs without the device;
  only the install needs it awake.
- A free Apple ID signature lasts ~7 days; after each reinstall the developer
  certificate must be trusted again in Settings → General → VPN & Device
  Management.

## 15. Invariants — do not undo these

Each of these was paid for with a bug or an explicit decision.

Where an invariant has a test that fails when it is undone, the test is named.
The rest are still prose, and prose does not fail a build — treat an unenforced
entry as the next one worth pinning, not as a weaker rule.

1. **No `distanceFilter` on the location manager**, no automatic pausing, and
   background updates on. The auto-pause detector only advances on delivered
   samples and nothing runs on wall-clock time, so anything that stops delivery
   means "stop moving ⇒ no callbacks ⇒ never auto-pause". All three, plus the
   `UIBackgroundModes` entries they need, are pinned by
   `LocationConfigurationInvariantTests`.
2. **Never derive speed from two consecutive fixes.** Use `SpeedEstimator`.
   Noise over a short baseline is indistinguishable from running.
3. **The motion gate may never block or delay a pause.** `CMMotionActivity`
   lags transitions; a stale "walking" would hold a stopped run open.
4. **"We don't know" is never "he is standing still."** Unknown and
   low-confidence motion samples abstain; a `nil` speed leaves accumulators
   untouched.
5. **Do not make stop detection more conservative.** The aggressive profile in
   7.3 was chosen deliberately, trading conservatism for resume reactivity.
6. **Starting from the Lock Screen must not force an unlock.** Sync on
   foreground instead.
7. **Auto-detected walks stay completely silent.**
8. **Never JSON-round-trip `Localizable.xcstrings`.** Pinned by
   `StringCatalogInvariantTests.theStringCatalogHasNoDuplicateKeys`, which counts
   key lines textually — a JSON parse cannot see a duplicate, the last one wins.
9. **Bump the build number in `project.yml`**, not in the generated plists.
10. **Timer keeps running through GPS gaps** (tunnels); only pauses stop it.
11. **A workout with no distance is never stored.** See section 5.
12. **A split faster than `ActivityStats.minimumPlausibleSplitSeconds` did not
    happen.** One re-acquired fix can close several kilometre boundaries at
    once; the zero-second splits that produces used to become the all-time
    "Fastest 1 km" and fire a bogus achievement.
13. **Every `upsertWorkout` call passes every column it wants kept.** The method
    assigns `co2SavedGrams` and `autoStarted` unconditionally, so an omitted
    argument is a reset, not a no-op.
14. **A save that did not become durable is never described as saved** — in the
    return value (`isLocallyDurable`) *and* in the UI copy the user reads.
15. **Localized format strings use `%lld` with `Int64`**, never `%d` with `Int`.
    Pinned by `StringCatalogInvariantTests` on both sides — the catalog and the
    `String(localized:)` call sites. Scoped to localized strings on purpose: a
    hard-coded format that never reaches the catalog is out of scope, and
    `Format.duration` builds "1:23:45" with `%d` correctly.

## 16. Open and unverified

- **Siri phrase matching has never been confirmed on device.** Built 2026-07-29;
  ask before building anything on top of it.
- **The motion gate and session traces have never run through a real workout.**
  They shipped in build 21 and were merged before field validation.
- **The 2026-09-05 audit fixes are unverified in the field.** They ship in
  build 24 and were proven only against the test suite. Four of them are now
  also pinned by unit tests (`ViewDerivationTests`), which is not the same as
  having been seen to work outside.
- **No real session trace has ever been committed**, so §7.6's promise is
  unfulfilled and every replay test feeds `TraceReplay` a synthetic trace.
  [`FIELD-CHECKLIST.md`](FIELD-CHECKLIST.md) is one outdoor session that closes
  this and the three items above it; the trace step is the one that makes the
  result permanent.
- No sharing for Monthly Wrapped (deferred, not dropped).
- `autoStarted` on `WorkoutRec` is surfaced in no UI; it exists so "why is this
  walk here" has an answer.
