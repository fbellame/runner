# Historical log — not maintained

Every document under `specs/` and `plans/` describes one epic **as it was
designed at the time**. They are kept because the reasoning is worth having:
what was considered, what was rejected, and why. They are *not* updated when
later work changes the behaviour they describe, and several of them are now
partly wrong.

**For what the app does today, read [`../SPEC.md`](../SPEC.md).**

Use these files to answer "why is it like this?" — never "how does it work?".
`SPEC.md` section 17 maps each version to its design document.
